# GhostControl

**一个无需代理的软件 KVM，像真人一样操作你自己的电脑。**

它在你的第二台电脑上完成真实的操作：**读取屏幕、判断当前所处的状态，然后打字和点击**——
在目标机看来，这就是一套真实的物理键盘和鼠标。目标机上不安装任何东西。

而且，和其他任何软件 KVM 都不同，它**在每次操作前都会核对屏幕，拒绝在错误的窗口里动手**：
因此任务绝不会落到锁屏上，也不会跑进不相干的应用。

> **用于你自己的电脑。** 你的两台电脑、两根线，再加上你本人。适用范围与威胁模型见
> [SECURITY.md](../SECURITY.md)。

## 它能帮你自动化什么

GhostControl 帮你省下盯着第二台电脑的时间。你用 JSON 写好小任务（或直接套用示例），它就会
替你完成日常和工作中最常见的那类桌面操作——而且只在屏幕确实是任务所预期的那一个时才动手：

- **回复聊天和消息**——WhatsApp Web、Telegram、Slack、Teams：发现新消息、打出回复、发送。
- **让电脑保持活动，不自动关机**——在长任务期间阻止它休眠、锁屏或进入空闲，无需改动电源设置。
- **回复和整理邮件**——打开客户端、读取屏幕内容、打出回复、归档。
- **编辑电子表格**——打开 Excel 或 Google Sheets、录入数据、触发重新计算、保存。
- **填写表单、录入数据**——面向没有 API 的网页或桌面应用做重复性输入。
- **操作那些屏蔽机器人和宏的应用**——由于输入是真实的 USB-HID，连拒绝脚本的软件也照样接受。
- **深夜无人值守地批量运行**——把任务排成队列；它会先核对每一个屏幕，所以绝不会在错误的
  窗口里触发。
- **远程操作第二台（或无显示器的）电脑**——那台机器上不装代理、驱动或远程桌面软件。

一句话：**面向第二台电脑的、无需代理的桌面自动化（RPA）**，靠屏幕核对确保任务永远不会
打字到不该打的地方。

## 为什么选它

其他软件 KVM 都在盲目地转发你的按键：它不知道哪个窗口在焦点上，屏幕一旦重新锁定就会把
你的输入吞掉，而且哪怕什么都没发生，它也照样报告"已发送"。GhostControl 则像坐在键盘前的人一样
把整个过程闭环：

1. **读取屏幕。** 采集 HDMI 画面，判别屏幕上真正显示的是什么——桌面、正确的应用、锁屏、
   对话框。
2. **判断状态。** 如果屏幕不是任务所预期的，它会整批放弃，而不是打字到错误的地方。
3. **在真实硬件上动作。** 通过 CH9329 打字和点击，再回读屏幕，确认操作确实生效了。

这正是硬件 KVM 和软件 KVM 两边都跳过的一步——它们只管转发输入，从不需要去相信一张截图。

## 它是什么——又不是什么

**它是**一个系统级的自动化与远程控制工具，面向操作系统已经运行起来的电脑。无代理、无驱动、
目标机上也没有远程桌面软件——它看起来就是一个坐在键盘前的人。

**它不是**硬件 KVM。**没有电源控制、没有 BIOS/UEFI 访问、没有虚拟介质。** 如果你需要
开机前的控制，请改用基于树莓派的 IP-KVM（PiKVM、TinyPilot）。老实交代的边界见
[HARDWARE.md](../HARDWARE.md)。

## 特性

- **故障即停（fail-closed）的核对**——每次操作前先给屏幕分类，拒绝错误状态，并靠回读确认
  每一步操作。
- **真实 HID 输入**——一个 CH9329 桥接器，目标机无法把它和物理键鼠区分开。无代理。
- **国际键盘**——可插拔布局（US、ABNT2 等）。当前布局打不出来的字符会被拒绝，而不会以
  错误的字形输出。
- **实测，而非拍脑袋**——一份[硬件指南](../HARDWARE.md)，记录了我们实测到的各种坑，外加
  一本[工程日志](../LEARNINGS.md)，写清楚什么出了问题、为什么。

## 怎么连接

```
[ 目标机 ] --HDMI out--> [ 采集棒 ]            --USB--> [ 控制机 ]
[ 目标机 ] <--USB HID--- [ CH9329 + CH340 ]  <--USB-- [ 控制机 ]
```

两台电脑、两根线。控制机写出 JSON 任务文件；守护进程在目标机上执行它们，并回读屏幕。
配件清单（约 US$15–25）见 [HARDWARE.md](../HARDWARE.md)。

## 快速上手

```bash
git clone https://github.com/bittricks/ghostcontrol
cd ghostcontrol
pip install -r requirements.txt

# 启动守护进程（自动识别串口；--layout 指定目标机键盘布局，默认 abnt2）
python src/agent_daemon.py --layout us
```

完整的安装、接线与校准见 [`docs/`](..)。

## 状态

验证核心由一套测试（400+）覆盖，其中包括一个架构边界测试，确保引擎里不混入特定于
应用的代码。

## 安全

它用你的凭据，控制你自己的一台电脑。**默认不开放任何网络端口**——它只跟硬件打交道，
不跟网络。在对外暴露任何东西之前，以及想报告漏洞时，请先读 [SECURITY.md](../SECURITY.md)。
